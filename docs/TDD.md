# 1. System Overview
FasoLocal is a full-stack Next.js 16 application using the App Router. React
Server Components render product pages on the server for SEO and low-bandwidth
performance; client components handle the cart, checkout forms, and modals. The
database is PostgreSQL accessed via Prisma ORM; authentication is handled by
NextAuth.js v5 with JWT sessions. Payments go through CinetPay (Orange Money +
Moov Money + Coris Money), with cash-on-delivery as a fallback for Ouagadougou.
The app is deployed on Vercel with auto-deploy from GitHub Actions on every push
to `master`.

## 1.1 High-Level Architecture
| Layer | Technology | Responsibility | Hosting |
| --- | --- | --- | --- |
| Presentation | Next.js 16 RSC + React 18 | UI, routing, SSR, server actions | Vercel (Edge + Node) |
| Client State | React Context (Cart/Auth) | Cart, session, toast | Browser (localStorage for cart) |
| API | Next.js Route Handlers (`/api/*`) | Data mutations, webhooks | Vercel (Node runtime) |
| Data access | Prisma ORM (singleton client) | Typed queries, migrations | — |
| Database | PostgreSQL 15 | All relational data | Neon / Supabase / RDS (TBD) |
| Auth | NextAuth.js v5 (JWT) | Sign-in, sessions, OAuth | Vercel |
| Payments | CinetPay REST API | Mobile money, webhook verification | CinetPay |
| File Storage | TBD (Vercel Blob / S3) | Product images | TBD |
| CI/CD | GitHub Actions | Lint, build, deploy | GitHub + Vercel |

# 3. Database Schema
The database is hosted on Supabase (PostgreSQL 15). All tables use UUID primary keys generated by uuid_generate_v4(). Row Level Security (RLS) is enabled on all user-facing tables. Schema migrations are managed via the supabase/schema.sql file and the Supabase CLI.

## 3.1 Entity Relationship Overview
| Table | Primary Key | Foreign Keys | Notes |
| --- | --- | --- | --- |
| sellers | id (uuid) | — | One seller can have many products |
| categories | id (text) | — | Enum-like: agroalimentaire, artisanat, etc. |
| products | id (uuid) | category → categories.id seller_id → sellers.id | Active flag controls catalog visibility |
| user_profiles | id (uuid) | References auth.users(id) | Extends Supabase Auth user |
| orders | id (uuid) | user_id → user_profiles.id | Status enum: pending/confirmed/shipped/etc. |
| order_items | id (uuid) | order_id → orders.id product_id → products.id | Stores price at time of purchase |
| reviews | id (uuid) | product_id → products.id user_id → user_profiles.id | Unique constraint: one review per user/product |


## 3.2 Key Table: products
| Column | Type | Constraints | Description |
| --- | --- | --- | --- |
| id | uuid | PK, NOT NULL | Auto-generated UUID |
| name | text | NOT NULL | Display name of the product |
| slug | text | UNIQUE, NOT NULL | URL-friendly identifier (e.g. miel-pur-ouagadougou) |
| description | text | — | Full product description |
| price | integer | NOT NULL | Price in FCFA (whole numbers only) |
| category | text | FK → categories.id | Category identifier string |
| seller_id | uuid | FK → sellers.id, ON DELETE CASCADE | Owner seller |
| badge | text | — | Quality badge: Bestseller \| Bio \| Certifie \| Local \| Export |
| emoji | text | DEFAULT '📦' | Display emoji for placeholder image |
| weight | text | — | Display weight/volume (e.g. '500g', '1kg') |
| stock | integer | DEFAULT 0 | Available inventory count |
| rating | numeric(3,2) | DEFAULT 0 | Average star rating (0.00–5.00) |
| review_count | integer | DEFAULT 0 | Denormalized review count for performance |
| active | boolean | DEFAULT true | Controls catalog visibility; admin can deactivate |
| created_at | timestamptz | DEFAULT now() | Record creation timestamp |


## 3.3 Row Level Security Policies
RLS is enabled on all sensitive tables. The following policies define access control:

| Table | Operation | Role | Policy Condition |
| --- | --- | --- | --- |
| products | SELECT | Public | active = true |
| products | INSERT | Seller | auth.uid() = seller_id |
| products | UPDATE | Seller | auth.uid() = seller_id |
| orders | SELECT | Buyer | auth.uid() = user_id |
| orders | INSERT | Buyer | auth.uid() = user_id |
| order_items | SELECT | Buyer | order_id IN (SELECT id FROM orders WHERE user_id = auth.uid()) |
| reviews | SELECT | Public | true (all reviews public) |
| reviews | INSERT | Buyer | auth.uid() = user_id |
| user_profiles | SELECT | Owner | auth.uid() = id |
| user_profiles | UPDATE | Owner | auth.uid() = id |



# 4. Frontend Component Architecture
## 4.1 Routing Structure
React Router v6 is used for client-side routing. All routes are defined in App.jsx. The Vercel vercel.json rewrites all paths to index.html to support SPA navigation. The Navbar and Footer are rendered outside Routes so they persist across all pages.

| Route | Component | Notes |
| --- | --- | --- |
| / | pages/Home.jsx | Landing page with hero, featured products, trust strip |
| /boutique | pages/Shop.jsx | Full catalog with category + search filtering via Zustand store |
| /produit/:slug | pages/ProductDetail.jsx | Dynamic route — slug maps to product in data.js / Supabase |
| /vendeurs | pages/Sellers.jsx | Seller directory with join CTA |
| /panier | pages/Cart.jsx | Cart page — reads from useCartStore |
| * | pages/NotFound.jsx | 404 catch-all |


## 4.2 State Management
State is managed with Zustand. Two stores are defined in src/lib/store.js:

| Store | Persistence | State & Actions |
| --- | --- | --- |
| useCartStore | localStorage (persist) | items[], addItem(), removeItem(), updateQty(), clearCart(), getTotal(), getCount() |
| useSearchStore | Session only | query, category, setQuery(), setCategory() |


The cart store uses Zustand's persist middleware, writing to localStorage under the key 'fasolocal-cart'. This means the cart survives page refreshes and browser restarts. The search store is ephemeral — category and query reset on navigation away.

## 4.3 ProductCard Component
src/components/product/ProductCard.jsx is the primary reusable product tile. It accepts a single product prop and reads addItem from useCartStore. It handles its own 'added' feedback state locally with a 1500ms auto-reset timeout.

| Prop | Type | Description |
| --- | --- | --- |
| product | object | Full product object from PRODUCTS array or Supabase query result |



# 5. Supabase Integration
## 5.1 Client Configuration
The Supabase client is initialized once in src/lib/supabase.js and exported for use throughout the app. Configuration is read from Vite environment variables.

| Environment Variable | Value |
| --- | --- |
| VITE_SUPABASE_URL | https://[project-ref].supabase.co — from Supabase project Settings > API |
| VITE_SUPABASE_ANON_KEY | Anon/public JWT key — safe to expose in browser context. RLS enforces security. |


Note: Never commit .env to version control. Only .env.example should be committed. Add both variables as GitHub Secrets and Vercel Environment Variables for CI/CD deployments.

## 5.2 Query Helpers
src/lib/supabase.js exports helper functions that wrap Supabase queries. These are called from page components and will replace the static data.js once the database is seeded in production.

| Function | Parameters | Returns |
| --- | --- | --- |
| getProducts(filters) | { category?, search? } | Array of product objects joined with sellers(name, location) |
| getProductBySlug(slug) | slug: string | Single product with full sellers(*) join |
| createOrder(orderData) | Order payload object | Created order record with id |


## 5.3 Authentication Flow
Authentication is handled by Supabase Auth. The planned flow for v1.0 is:

| # | Step | Implementation Detail |
| --- | --- | --- |
| 1 | User submits email + password | supabase.auth.signUp() — creates auth.users record and triggers email confirmation |
| 2 | Email confirmed | Supabase sends magic link; user_profiles row created via Postgres trigger or post-auth hook |
| 3 | Login | supabase.auth.signInWithPassword() — returns session with JWT access token |
| 4 | Session persistence | Supabase JS SDK stores session in localStorage automatically; auto-refreshes token |
| 5 | Protected routes | React Router component checks supabase.auth.getUser() — redirect to /login if null |
| 6 | Logout | supabase.auth.signOut() — clears session and Zustand cart store |


## 5.4 File Storage — Product Images
Product images are stored in Supabase Storage. A dedicated bucket named product-images is created with public read access (RLS policy: SELECT is public). Uploads are restricted to authenticated sellers only.

- Bucket name: product-images
- Max file size: 5MB per image
- Accepted MIME types: image/jpeg, image/png, image/webp
- CDN URL pattern: https://[project-ref].supabase.co/storage/v1/object/public/product-images/[seller_id]/[filename]
- Client-side: compress to WebP with max dimension 1200px before upload using browser-image-compression npm package


# 6. Payment Integration (CinetPay)
Mobile money payments are processed through CinetPay, which provides a unified API for Orange Money, Moov Money, and Airtel Money in Burkina Faso. The integration follows the CinetPay Payment Link / Checkout Widget approach.

## 6.1 Payment Flow
| # | Actor | Action |
| --- | --- | --- |
| 1 | Buyer (Frontend) | Selects payment method and clicks 'Passer la commande' |
| 2 | Frontend | POSTs order data to Supabase Edge Function /functions/v1/create-payment |
| 3 | Edge Function | Calls CinetPay /payment API with amount, transaction_id, currency (XOF), notify_url, return_url |
| 4 | CinetPay | Returns payment_url for the checkout redirect |
| 5 | Buyer | Redirected to CinetPay hosted checkout; enters mobile money PIN |
| 6 | CinetPay | Sends webhook POST to /functions/v1/payment-webhook with payment_status |
| 7 | Edge Function | Verifies webhook signature, updates orders.payment_status and orders.status in Supabase |
| 8 | Buyer | Redirected back to FasoLocal /commande/confirmation?id=[order_id] |


## 6.2 CinetPay Environment Variables
| Variable | Usage |
| --- | --- |
| CINETPAY_API_KEY | API key from CinetPay dashboard — stored as Supabase Edge Function secret |
| CINETPAY_SITE_ID | Site ID from CinetPay — identifies your merchant account |
| CINETPAY_NOTIFY_URL | https://[project-ref].supabase.co/functions/v1/payment-webhook |
| CINETPAY_RETURN_URL | https://fasolocal.com/commande/confirmation — post-payment redirect |



# 7. CI/CD Pipeline
Deployments are automated via GitHub Actions defined in .github/workflows/deploy.yml. The pipeline runs on every push to main and on every pull request targeting main.

## 7.1 Pipeline Stages
| Stage | Trigger | Actions |
| --- | --- | --- |
| Build & Lint | All pushes & PRs | npm ci → npm run lint → npm run build (with Supabase env vars injected from GitHub Secrets) |
| Artifact Upload | All pushes & PRs | dist/ folder uploaded as GitHub Actions artifact for inspection |

# 9. Performance & Security Considerations
## 9.1 Performance
- Vite code splitting: React Router's lazy() and Suspense will wrap each page component to split bundles per route (Phase 2 optimization).
- Images: all product images compressed to WebP client-side before upload. Served via Supabase CDN with far-future cache headers.
- Tailwind CSS: purged at build time — only used classes included in the production bundle. Expected CSS output < 15KB gzipped.
- Supabase indexes: products.category, products.slug, and orders.user_id are indexed to keep catalog queries under 100ms.
- Cart state is managed client-side only — no round-trip to server for add-to-cart interactions.

## 9.2 Security
- Row Level Security (RLS) enforced at the database layer — unauthorized queries return empty results, not errors.
- Supabase anon key is safe to expose in the browser — it cannot bypass RLS. Service Role key is never used client-side.
- HTTPS enforced on Vercel for all traffic. HTTP requests automatically redirected.
- Auth tokens are JWT-signed by Supabase and automatically refreshed by the SDK before expiry.
- Input validation: all form inputs validated client-side before submission. Supabase constraints enforce server-side integrity (NOT NULL, type constraints).
- CinetPay webhooks verified by API signature header before any order status updates are applied.
